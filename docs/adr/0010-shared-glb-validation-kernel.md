# ADR-0010: Shared GLB validation kernel

## Status

Accepted.

## Context

The runtime catalog loader owned GLB actual-byte parsing and validation. Wave C
frame generation must validate its output against the same supported profile.
Copying the checks into generation would allow runtime and production tooling to
diverge on headers, chunks, scene reachability, accessors, buffers, finite
POSITION bytes, bounds, or metre units.

## Decision

`packages/assets` owns the dependency-free supported-GLB validation kernel.
Runtime catalog admission and frame generation both call it. Contracts continue
to parse catalog and manifest JSON, the runtime app continues to own network,
origin, digest-chain, deployment, and mode admission, and generation continues
to own geometry and immutable bundle construction.

The kernel accepts actual bytes plus required nodes, metre unit, and optional
expected bounds. It returns actual POSITION bounds derived from embedded bytes.
Bounds include only meshes referenced by nodes reachable from the active scene;
unreachable mesh/accessor bytes are still structurally and numerically checked.
The supported profile permits only triangle primitives and decodes unsigned
indices with their declared layout to enforce each index against POSITION count.
Non-indexed POSITION counts and indexed index counts must each be divisible by
three.

The supported profile does not compute transformed world-space bounds. Instead,
it rejects any matrix, translation, rotation, or scale property on a reachable
mesh node or any ancestor along a path to that mesh, including identity-valued
transforms. This makes raw reachable POSITION bounds equal rendered mesh bounds.
Finite, correctly sized transforms remain allowed on transform-only leaf nodes
such as nose and hinge anchors because they cannot affect admitted mesh geometry.
Matrix and TRS properties cannot be combined on one node, and reachable cycles
are rejected.
It performs no I/O, network access, publication, or status transition.

## Consequences

- Generated bytes and runtime-loaded bytes cannot silently use different GLB
  admission rules.
- Existing runtime hash/origin/deployment/admission behavior is unchanged.
- Proxy output is still calibration-only draft fixture data; validation does not
  grant approval, publication, `recommendedForLive`, G1 readiness, or G2 status.
